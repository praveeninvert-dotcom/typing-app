```tsx
return (

        key="test"
        variants={screenVariants}
        initial="initial"
        animate="animate"
        exit="exit"
        transition={screenTransition}
        style={{ width: '100%', height: '100%' }}
      >
        <TestScreen key={testKey} difficulty={difficulty} onFinish={handleTestFinish} />
      </motion.div>
    )}

    {screen === 'result' && result !== null && (
      <motion.div
        key="result"
        variants={screenVariants}
        initial="initial"
        animate="animate"
        exit="exit"
        transition={screenTransition}
        style={{ width: '100%', height: '100%' }}
      >
        <ResultOverlay result={result} onRetry={handleRetry} onHome={handleHome} />
      </motion.div>
    )}

    {/* Fallback: should never reach — keep for type safety */}
    {screen !== 'home' && screen !== 'test' && screen !== 'result' && (
      <motion.div
        key="fallback"
        variants={screenVariants}
        initial="initial"
        animate="animate"
        exit="exit"
        transition={screenTransition}
        style={{ width: '100%', height: '100%' }}
      >
        <HomeScreen onStart={handleStart} />
      </motion.div>
    )}
  </AnimatePresence>
)
```

CRITICAL constraints:
- `mode="wait"` on AnimatePresence is required — ensures exit completes before entry starts (outgoing 200ms fade, then incoming 200ms fade)
- The `key` on each `motion.div` must be stable and unique per screen — `"home"`, `"test"`, `"result"` — so AnimatePresence can track enter/exit
- The inner `<TestScreen key={testKey} ...>` key ensures TestScreen remounts on Retry without changing the outer motion.div key
- Do NOT move existing state or handler logic — only restructure the return JSX and add `testKey` state
- `framer-motion` is already in package.json — do NOT add it again
- The `style={{ width: '100%', height: '100%' }}` on motion.div prevents layout disruption — screens already handle their own centering
