TestScreen orchestrates: hidden input + useTypingEngine + useCountdown + StatsBar + TextDisplay + ResultOverlay trigger.


Internal hooks:
1. `generateText(difficulty)` — called once on mount via useMemo or direct initialization
2. `useTypingEngine({ words, onStart, onFinish })` — the typing engine
3. `useCountdown({ onComplete })` — the timer
4. `useKeystrokeSound()` — stub in Phase 1
5. `inputRef` — for auto-focus and re-focus

Key behaviors:
- Words generated once: `const [words] = useState(() => generateText(difficulty))` (lazy initializer ensures stable reference)
- `onStart` callback: calls `countdown.start()` (wired from useTypingEngine → useCountdown)
- `onFinish` callback from useTypingEngine: compute result and call props.onFinish
- `onComplete` from useCountdown: compute result and call props.onFinish
- Both paths use the same result computation:

**TypingApp (components/TypingApp.tsx)**

This is the root state machine per CLAUDE.md architecture rules:
- All screen transitions live here
- Screen state: `'home' | 'test' | 'result'`
- No useRouter, no Link, no next/navigation

State:
```typescript
const [screen, setScreen] = useState<Screen>('home')
const [difficulty, setDifficulty] = useState<Difficulty | null>(null)
const [result, setResult] = useState<ResultState | null>(null)
```

Transition handlers:
- `handleStart(d: Difficulty)`: set difficulty=d, screen='test'
- `handleTestFinish(r: ResultState)`: set result=r, screen='result'
- `handleRetry()`: screen='test' (keep same difficulty; TestScreen regenerates words on mount)
- `handleHome()`: screen='home', difficulty=null, result=null

Rendering:
```tsx
'use client'
export function TypingApp() {
  // state...
  if (screen === 'home') {
    return <HomeScreen onStart={handleStart} />
  }
  if (screen === 'test' && difficulty !== null) {
    return <TestScreen difficulty={difficulty} onFinish={handleTestFinish} />
  }
  if (screen === 'result' && result !== null) {
    return <ResultOverlay result={result} onRetry={handleRetry} onHome={handleHome} />
  }
  // Fallback — should never reach here if transitions are correct
  return <HomeScreen onStart={handleStart} />
}
```

No Framer Motion imports in Phase 1 (per CONTEXT.md locked decision). Screen transitions are instant — AnimatePresence is Phase 3.

IMPORTANT: ResultOverlay renders OVER the TestScreen in the real design (as a modal). But for Phase 1 without animations, the simpler approach is to render ResultOverlay as a full-page replacement (same as other screens), since the backdrop + modal CSS in ResultOverlay.module.css already creates the visual overlay effect even when it's the only thing rendered. This keeps Phase 1 simple — Phase 3 will adjust to true overlay when AnimatePresence is added.
